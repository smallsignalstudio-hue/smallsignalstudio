10 · Mock answers (say out loud)

Q: How does GC work?

Objects live on the heap. GC walks from roots and keeps the reachable set; the rest is garbage. Generational: short-lived die in Eden; long-lived promote to Old. Pauses affect latency. Prod: allocation + leaks first → measure → then tune.

Q: Which GC?

Services → G1. Batch → Parallel. Proven GC-broken p99 on Java 21+ → ZGC. Watch Serial on tiny pods.

Q: Frequent Full GC?

G1 Full GC = alarm. Log cause: humongous / to-space / late mark. Parallel check: heap dump for leak.

Q: How do you optimize GC?

Mechanism (G1 regions, Young+Mixed) → trade-off (pause↓ costs CPU; ZGC costs RAM) → measure (log/JFR/MAT) → decide from data. Cut allocation in code first.
Wall line: Mids recite flags. Seniors measure first, then decide.
